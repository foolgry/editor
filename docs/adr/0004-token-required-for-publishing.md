# 发布一律需要令牌，关闭匿名发布

原先只有"归入项目"的发布需要凭证，发布独立单篇（`/s/<id>`）保持匿名公开（见 ADR-0002）。现在改为：**任何发布都必须携带有效令牌（或站长主密码）**，凭证缺失或无效一律 401，响应里带上申请入口 `/apply`；图片上传（`/api/upload`）同属写操作，一并要求凭证。

理由：域名托管风险不可逆。匿名发布意味着任何人都能用本站域名发布内容，一旦被拿去发钓鱼、垃圾或侵权内容，事后清理的代价远高于事前加一道门槛；而且发布者不可追溯，"按令牌限流、按令牌吊销"这类治理手段全都无从谈起。ADR-0002 把匿名发布当作"现状不变"保留，是因为当时的边界只画在项目上；现在把边界画在**写操作**上，与 CONTEXT.md 里"发布者是站长本人及其授权的 Agent"的定义对齐。

**Considered Options**：用 IP 做速率/数量限制来替代凭证——只能提高滥用成本，NAT 共享出口会误伤整片用户、IPv6 与 VPN 易于绕过，而且解决不了内容托管的可追溯性问题，只能作为辅助手段，不足以作为唯一防线，拒绝；让 skill 脚本自报 MAC 地址做身份——MAC 是二层地址，每经过一跳就被改写，服务端永远观测不到，客户端自报等同于可伪造，技术上不成立，拒绝。

**Consequences**：首次发布者必须先从 `/apply` 联系站长领取令牌，发布门槛从"零"变成"一次申请"；编辑器在无令牌时展示申请入口而非静默失败，令牌存 localStorage，之后发布免填。已发出的分享链接不受影响，读者侧仍然完全公开无需认证。
