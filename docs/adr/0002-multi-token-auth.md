# 多令牌认证替代单一管理密码，不做用户系统

原系统只有一个站长主密码（`X-List-Password`），发布接口完全公开。为了让少数熟人和多个 Agent 都能发布文章、使用项目功能，我们引入**多令牌机制**：站长签发多个命名令牌，令牌是所有写操作（发布挂载、项目管理）的凭证，可单独吊销；内容归属创建它的令牌，权限边界为"令牌管自己名下的，主密码管一切并独占令牌签发"。

**Considered Options**：完整用户系统（注册/登录/session）——对单文件 Go + SQLite 的自托管工具过重，且目标用户只是少数熟人，拒绝。保持公开发布 + 项目功能也公开——任何人都能建项目、往他人项目塞内容，安全不可接受，拒绝。

**Consequences**：发布独立单篇保持匿名公开（现状不变），一旦请求涉及项目就必须携带令牌。编辑器主页通过 localStorage 保存令牌，匿名访客体验不变。

> 后续修订：本条"独立单篇匿名公开"的部分已被 [ADR-0004](0004-token-required-for-publishing.md) 推翻——现在任何发布都必须携带令牌。令牌机制本身（多令牌、可单独吊销、归属创建者、主密码独占签发）保持不变。
