# 项目是可选容器，一篇分享最多属于一个项目

我们为分享功能引入了"项目"（聚合多篇分享、有独立链接的命名集合）。决策：**项目是可选容器**——单篇分享（`/s/<id>`）保持现状不变，不强制归属任何项目；且**一篇分享最多属于一个项目**（`shares.project_id` 单一外键），不做多对多。

理由：向后兼容现有链接和 skill 的发布行为；实际场景（日报、巡检）是"先有文章、再聚合"，而非"先建项目才能发文章"；多对多会引入目录排序、归属冲突等复杂度，而"一篇精选进多个合集"的需求目前不存在。

**Consequences**：删除项目不级联删除文章（只删容器，文章变回独立单篇，已发出的链接全部存活）。若未来出现多合集需求，需要新建关联表迁移，成本可接受。
